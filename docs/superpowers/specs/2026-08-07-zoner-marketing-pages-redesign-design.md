# 마케팅 3화면 재작성 — FAQ · Pricing · UserGuide

날짜: 2026-08-07
선행 문서: `2026-08-05-zoner-design-system-design.md`, `2026-08-07-zoner-dynamic-ui-design.md`
상태: 구현 완료 (2026-08-07)

## 문제

로그인 전에 보는 세 화면만 디자인 시스템 밖에 있다. 측정 결과:

| 화면 | 토큰 참조 | 하드코딩 색 | `h1~h6` | `main` | `section` | `nav` | `div` |
|---|---|---|---|---|---|---|---|
| FAQ | 0 | 42 | 0 | 0 | 0 | 0 | 11 |
| Pricing | 0 | 28 | 0 | 0 | 0 | 0 | 17 |
| UserGuide | 0 | 21 | 0 | 0 | 0 | 0 | 7 |
| Home (비교) | 41 | 0 | 3 | 0 | 3 | 0 | 3 |

나머지 9개 화면(Home·Login·SignUp·Save·Trash·Mypage·StartLearning·
SessionReport·AiChat)은 토큰 33~107개를 쓰고 하드코딩 색이 0~3개다. 깔끔한
이분법이며, 경계는 정확히 "로그인 전 / 로그인 후"다.

### 원인

클래스명이 `ZONER`, `text-wrapper-U`다. 디자인 툴에서 내보낸 코드이고 코드베이스의
BEM 규칙(`start-learning__video-wrap`)과 무관하다. **옛 디자인이 아니라 한 번도
코드베이스 규약에 편입되지 않은 수입 코드다.** `text-wrapper-U`를 유지보수할
방법은 없으므로 리스킨이 아니라 재작성이 맞다.

### 두 가지 결함

1. **시각적 단절.** 흰 배경·검은 네비·빨간 강조 대 네이비·시안. 같은 서비스로
   읽히지 않는다. FAQ에서 로그인으로 넘어가는 순간 다른 제품처럼 보인다.
2. **접근성 실패.** 제목과 랜드마크가 하나도 없다. 스크린리더 사용자는 구조를
   전혀 얻지 못한다 — 제목으로 건너뛸 수도, 본문 시작점을 알 수도 없다.
   미관 문제가 아니라 WCAG 위반이다.

### 중복

세 화면이 각자 네비게이션을 하드코딩으로 중복 구현했다. 이미 이전이 끝난 공용
`NavBar`(토큰 21, 하드코딩 0)가 있는데 **Home과 Login만 쓴다.**

## 결정

- **제품과 동일한 다크로 통일한다.** 기존 `tokens.css`를 그대로 쓴다. 라이트
  시맨틱 계층을 새로 만들지 않는다 — `tokens.css`에는 현재 다크 값만 있고,
  라이트를 추가하면 전 화면 대비비를 다시 검증해야 한다.
- **레이아웃까지 재설계한다.** 색만 바꾸면 균일한 카드 나열의 위계 없음이
  그대로 남는다.
- **중복 네비를 공용 `NavBar`로 교체한다.**

## 공통 작업

1. 세 화면의 JSX를 시맨틱 구조로 다시 쓴다
   - `<main>` 하나, 논리 블록마다 `<section aria-labelledby>`
   - `h1` → `h2` 순서를 건너뛰지 않는다. 크기는 CSS로 정한다
   - 목록은 `<ul>`/`<li>`. FAQ 질문 묶음이 대표적이다
2. 클래스명을 BEM으로 바꾼다 (`faq__question`, `pricing__tier`)
3. 하드코딩 색 91개를 전부 의미 토큰으로 교체한다. 원시 토큰을 컴포넌트에서
   직접 참조하지 않는다
4. 각 화면의 자체 네비를 지우고 `NavBar`를 쓴다
5. `hover` / `focus-visible` / `active` 상태를 설계한다. 전역
   `:focus-visible`은 `index.css`에 이미 있으므로 그 위에 필요한 것만 더한다

## 화면별

### FAQ

현재: 균일한 카드 3개를 가로로 나열한 것이 전부다. 위계가 없고, 질문 앞의
빨간 `?`가 유일한 강조다. 답변이 화면에 보이지 않는다.

방향: 질문 목록을 아코디언으로 만든다. 하나가 열리고 나머지는 접힌다.

- `<ul>` + `<li>` + `<button aria-expanded aria-controls>`
- 답변 영역은 `id`로 연결하고 `hidden` 토글
- 열림/닫힘 전환은 `grid-template-rows: 0fr → 1fr` 또는 `max-height`.
  `height: auto` 애니메이션은 동작하지 않는다
- 키보드: `Enter`/`Space`로 토글. `<button>`을 쓰면 공짜로 얻는다

### Pricing

현재 내용 미확인(160줄, `div` 17개). **구현 첫 단계는 실제 내용 목록화다.**
없는 요금제나 기능을 만들어 넣지 않는다.

방향: 요금제 카드에 위계를 준다 — 추천 등급 하나를 시각적으로 키우고 나머지는
작게. 균일 3열은 쓰지 않는다. 등급 간 차이는 색만이 아니라 크기·배치로도
드러낸다.

### UserGuide

현재 내용 미확인(127줄, `div` 7개). 마찬가지로 내용 목록화가 먼저다.

방향: 단계별 안내이므로 번호가 매겨진 순서 목록(`<ol>`)이 자연스럽다.
`jsx-a11y/img-redundant-alt` 경고 3건이 이 화면에 있으므로 함께 해결한다 —
`alt`에서 "이미지/사진" 표현을 뺀다. 현재 빌드의 유일한 코드 경고다.

## 모션

`2026-08-07-zoner-dynamic-ui-design.md`의 원칙을 따른다. 라우트 진입 페이드는
이미 전역으로 걸려 있으므로 화면별로 다시 넣지 않는다. 아코디언 열림처럼
상태 변화를 설명하는 모션만 더한다. 장식적 움직임은 추가하지 않는다.

## 검증

- 세 화면 모두 하드코딩 색 0개 (`grep -cE '#[0-9a-fA-F]{3,8}|rgba?\(|white|black'`)
- 세 화면 모두 `h1` 1개 + 순서를 지키는 하위 제목, `<main>` 1개
- 키보드만으로 전체 플로우 수행 가능, 포커스 표시가 항상 보임
- 320 / 768 / 1024 / 1440에서 가로 스크롤 없음

- `Report_Image.css`는 임포트하는 곳이 없는 죽은 파일이다. 이번 작업 중

계수 방법: **토큰 참조** = 화면 CSS 파일의 `var(--` 출현 수. **하드코딩 색** =
JS·CSS 양쪽에 문서의 grep(`#[0-9a-fA-F]{3,8}|rgba?\(|white|black`)을 적용한 수.
제목·랜드마크·`div`는 렌더된 DOM 기준(`nav`는 `NavBar`가 제공하는 1개).

**앞머리 표의 "토큰 참조" 열과 직접 비교하지 말 것.** 그 표의 Home 41 / NavBar 21은
위 방법으로 재현되지 않는다(같은 파일을 이 방법으로 세면 73 / 32). 원본이 어떤
기준으로 셌는지 확인하지 못해, 여기서는 방법을 명시한 새 측정값만 싣는다.

방법과 무관하게 확정된 것: **하드코딩 색 91개 → 0개**, 제목·랜드마크 0개 →
세 화면 모두 `h1` 1개 + `main` 1개.

### 화면별로 한 것

**FAQ** — 균일 카드 3개 가로 나열을 아코디언 목록으로 바꿨다. `<ul>` + `<li>` +
`<button aria-expanded aria-controls>`, 답변은 `role="region" aria-labelledby`.
하나만 열리고, 첫 질문은 열어 둔 채 시작한다. 이전 화면은 답변이 hover에만
나타나 터치 기기와 스크린리더에서 아예 도달할 수 없었다.

**Pricing** — 구현 첫 단계로 실제 내용을 목록화했다. 요금제 3종(Basic 무료 /
Pro $7.99 / Premium $14.99)과 각 기능·타겟 문구는 전부 기존 JSX에 있던 문자열
그대로다. 없던 요금제나 기능은 넣지 않았다. 균일 3열 대신
`grid-template-columns: 1fr 1.32fr 1fr` 로 추천 등급(Pro)을 넓히고, 위로 띄우고,
강조 테두리와 채운 CTA를 줬다 — 크기·배치·색 세 축이 함께 위계를 만든다.

**UserGuide** — 절대좌표 배치를 `<ol>` 3단계로 바꿨다. 글과 그림이 좌우로
번갈아 놓이고, 1023px 아래에서는 한 열로 접히며 글이 항상 먼저 온다.
`alt="Image"` 3건을 실제 내용 설명으로 교체해 `jsx-a11y/img-redundant-alt`
경고를 없앴다. 이미지에 `width`/`height`를 명시하고 첫 장 외에는 `lazy`로 뒀다.

**공통** — 세 화면이 각자 중복 구현하던 네비게이션을 지우고 공용 `NavBar`를 쓴다.
클래스명은 BEM(`faq__trigger`, `pricing__tier--featured`, `guide__step`)으로 바꿨다.
`box-sizing` 리셋은 `index.css`에 화면 이름을 손으로 나열하는 대신 각 화면
CSS 파일 안에서 선언했다 — TS-011이 그 나열 방식 때문에 생긴 결함이다.

### 설계와 달라진 곳

**아코디언을 `hidden`이 아니라 `visibility`로 토글한다.** 문서는 `hidden` 토글과
`grid-template-rows: 0fr → 1fr` 전환을 둘 다 요구했는데, `hidden`은
`display: none`이라 전환이 시작조차 하지 않는다. `visibility`는 접근성 트리
제외 효과가 같으면서 전환 가능하고, 양 끝 중 하나가 `visible`이면 전환 구간
내내 `visible`로 유지돼 닫히는 모션이 끝까지 재생된다. 자세한 경위는
TROUBLESHOOTING **TS-015**.

**`tokens.css`에 `--color-on-accent`를 하나 추가했다.** "원시 토큰을 컴포넌트에서
직접 참조하지 않는다"를 지키려면 강조색 배경 위 글자색에 해당하는 의미 토큰이
필요한데 없었다(기존 화면은 `--navy-950`을 직접 참조하고 있었다). 값 변경 없이
추가만 했으므로 기존 9개 화면에 영향이 없다.

### 검증

| 항목 | 결과 |
|---|---|
| 하드코딩 색 0개 (문서의 grep) | FAQ·Pricing·UserGuide JS/CSS 6개 파일 전부 0 |
| 원시 토큰 직접 참조 | 0 |
| `h1` 1개 + 제목 순서 | `h1 → h2 → h3` 건너뜀 없음, 세 화면 모두 `main` 1개 |
| 가로 스크롤 (320/768/1024/1440) | 4개 폭 × 3화면 전부 `scrollWidth == clientWidth` |
| 본문 대비비 4.5:1 | 텍스트 조합 전부 통과, 최저 5.71:1 (muted on surface-alt) |
| 빌드 신규 경고 | 0 |
| `img-redundant-alt` 3건 | 해소 |
| 단위 테스트 | 214건 통과 (15 suites) |

**키보드.** 자동화 탭이 `visibilityState: hidden`이라 실제 Tab 키 입력이 페이지에
도달하지 않았다(TS-014와 같은 계열의 환경 제약). 키 주입 대신 키보드 접근성이
요구하는 성질을 DOM 수준에서 직접 검사했다.

- 양수 `tabindex` 0개 → Tab 순서가 DOM 순서를 벗어나지 않는다
- DOM 순서 == 시각 순서(위→아래, 같은 줄이면 왼→오) — 세 화면 모두 일치
- 모든 컨트롤이 `:focus-visible` + `outline ≥ 2px` — 미달 0개
- sticky NavBar에 가리는 포커스 대상 0개 (WCAG 2.2 Focus Not Obscured)
- `div` + `onclick` 같은 가짜 버튼 0개 — 전부 네이티브 `<button>`이라
  Enter/Space가 공짜로 따라온다
- 375px에서 접힌 메뉴의 링크 3개는 탭 순서에서 빠지고(`focusable: false`),
  토글로 열면 들어오며, `Esc`로 닫힌다

포커스 링은 별도로 확대 캡처해 육안으로도 확인했다.

### 범위 밖으로 남긴 것

- **`--color-border-strong`이 UI 경계 3:1(WCAG 1.4.11)에 미달한다** — surface 위
  2.83:1, surface-alt 위 2.52:1. 이번에 새로 쓴 곳은 `--color-text-muted`(6.41:1)로
  바꿨지만, 같은 토큰을 쓰는 `Login.css:46`·`SignUp.css:84`(입력 필드 테두리)와
  `AiChat.css:370`은 손대지 않았다. 이 문서가 "이미 이전이 끝난 9개 화면"을
  범위 밖으로 뒀고, 검증 없이 4개 화면 배색을 바꾸는 쪽이 위험이 크다.
  별도 작업으로 뺀다. TROUBLESHOOTING **TS-016**.
- `Report_Image.css` — 임포트하는 곳이 없고 UserGuide와도 무관해 문서 지시대로
  그대로 뒀다.
- `src/App.css` — 문서가 명시한 범위 밖. 건드리지 않았다.
- 라이트 테마 — 도입하지 않았다.

### 남은 확인

실제 브라우저에서 Tab 키를 눌러 보는 확인은 사용자 점검으로 남긴다. 위 DOM
검사가 같은 성질을 덮지만, 키 입력 경로 자체를 대신하지는 않는다.
