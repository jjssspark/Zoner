# 마케팅 3화면 재작성 — FAQ · Pricing · UserGuide

날짜: 2026-08-07
선행 문서: `2026-08-05-zoner-design-system-design.md`, `2026-08-07-zoner-dynamic-ui-design.md`
상태: 설계 확정, 구현 미착수

## 문제

로그인 전에 보는 세 화면만 디자인 시스템 밖에 있다. 측정 결과:

| 화면 | 토큰 참조 | 하드코딩 색 | `h1~h6` | `main` | `section` | `nav` | `div` |
|---|---|---|---|---|---|---|---|
| FAQ | 0 | 42 | 0 | 0 | 0 | 0 | 11 |
| Pricing | 0 | 28 | 0 | 0 | 0 | 0 | 17 |
| UserGuide | 0 | 21 | 0 | 0 | 0 | 0 | 7 |
| Home (비교) | 41 | 0 | 3 | 0 | 3 | 0 | 3 |

나머지 9개 화면(Home·Login·SignUp·Save·Trash·Mypage·StartLearning·
SessionReport·AiChat)은 토큰 33~107개를 쓰고 하드코딩 색이 0~3개다. 깔끔한
이분법이며, 경계는 정확히 "로그인 전 / 로그인 후"다.

### 원인

클래스명이 `ZONER`, `text-wrapper-U`다. 디자인 툴에서 내보낸 코드이고 코드베이스의
BEM 규칙(`start-learning__video-wrap`)과 무관하다. **옛 디자인이 아니라 한 번도
코드베이스 규약에 편입되지 않은 수입 코드다.** `text-wrapper-U`를 유지보수할
방법은 없으므로 리스킨이 아니라 재작성이 맞다.

### 두 가지 결함

1. **시각적 단절.** 흰 배경·검은 네비·빨간 강조 대 네이비·시안. 같은 서비스로
   읽히지 않는다. FAQ에서 로그인으로 넘어가는 순간 다른 제품처럼 보인다.
2. **접근성 실패.** 제목과 랜드마크가 하나도 없다. 스크린리더 사용자는 구조를
   전혀 얻지 못한다 — 제목으로 건너뛸 수도, 본문 시작점을 알 수도 없다.
   미관 문제가 아니라 WCAG 위반이다.

### 중복

세 화면이 각자 네비게이션을 하드코딩으로 중복 구현했다. 이미 이전이 끝난 공용
`NavBar`(토큰 21, 하드코딩 0)가 있는데 **Home과 Login만 쓴다.**

## 결정

- **제품과 동일한 다크로 통일한다.** 기존 `tokens.css`를 그대로 쓴다. 라이트
  시맨틱 계층을 새로 만들지 않는다 — `tokens.css`에는 현재 다크 값만 있고,
  라이트를 추가하면 전 화면 대비비를 다시 검증해야 한다.
- **레이아웃까지 재설계한다.** 색만 바꾸면 균일한 카드 나열의 위계 없음이
  그대로 남는다.
- **중복 네비를 공용 `NavBar`로 교체한다.**

## 공통 작업

1. 세 화면의 JSX를 시맨틱 구조로 다시 쓴다
   - `<main>` 하나, 논리 블록마다 `<section aria-labelledby>`
   - `h1` → `h2` 순서를 건너뛰지 않는다. 크기는 CSS로 정한다
   - 목록은 `<ul>`/`<li>`. FAQ 질문 묶음이 대표적이다
2. 클래스명을 BEM으로 바꾼다 (`faq__question`, `pricing__tier`)
3. 하드코딩 색 91개를 전부 의미 토큰으로 교체한다. 원시 토큰을 컴포넌트에서
   직접 참조하지 않는다
4. 각 화면의 자체 네비를 지우고 `NavBar`를 쓴다
5. `hover` / `focus-visible` / `active` 상태를 설계한다. 전역
   `:focus-visible`은 `index.css`에 이미 있으므로 그 위에 필요한 것만 더한다

## 화면별

### FAQ

현재: 균일한 카드 3개를 가로로 나열한 것이 전부다. 위계가 없고, 질문 앞의
빨간 `?`가 유일한 강조다. 답변이 화면에 보이지 않는다.

방향: 질문 목록을 아코디언으로 만든다. 하나가 열리고 나머지는 접힌다.

- `<ul>` + `<li>` + `<button aria-expanded aria-controls>`
- 답변 영역은 `id`로 연결하고 `hidden` 토글
- 열림/닫힘 전환은 `grid-template-rows: 0fr → 1fr` 또는 `max-height`.
  `height: auto` 애니메이션은 동작하지 않는다
- 키보드: `Enter`/`Space`로 토글. `<button>`을 쓰면 공짜로 얻는다

### Pricing

현재 내용 미확인(160줄, `div` 17개). **구현 첫 단계는 실제 내용 목록화다.**
없는 요금제나 기능을 만들어 넣지 않는다.

방향: 요금제 카드에 위계를 준다 — 추천 등급 하나를 시각적으로 키우고 나머지는
작게. 균일 3열은 쓰지 않는다. 등급 간 차이는 색만이 아니라 크기·배치로도
드러낸다.

### UserGuide

현재 내용 미확인(127줄, `div` 7개). 마찬가지로 내용 목록화가 먼저다.

방향: 단계별 안내이므로 번호가 매겨진 순서 목록(`<ol>`)이 자연스럽다.
`jsx-a11y/img-redundant-alt` 경고 3건이 이 화면에 있으므로 함께 해결한다 —
`alt`에서 "이미지/사진" 표현을 뺀다. 현재 빌드의 유일한 코드 경고다.

## 모션

`2026-08-07-zoner-dynamic-ui-design.md`의 원칙을 따른다. 라우트 진입 페이드는
이미 전역으로 걸려 있으므로 화면별로 다시 넣지 않는다. 아코디언 열림처럼
상태 변화를 설명하는 모션만 더한다. 장식적 움직임은 추가하지 않는다.

## 검증

- 세 화면 모두 하드코딩 색 0개 (`grep -cE '#[0-9a-fA-F]{3,8}|rgba?\(|white|black'`)
- 세 화면 모두 `h1` 1개 + 순서를 지키는 하위 제목, `<main>` 1개
- 키보드만으로 전체 플로우 수행 가능, 포커스 표시가 항상 보임
- 320 / 768 / 1024 / 1440에서 가로 스크롤 없음
- 본문 대비비 4.5:1 이상
- 빌드 신규 경고 0, 기존 `img-redundant-alt` 3건은 해소
- `Report_Image.css`는 임포트하는 곳이 없는 죽은 파일이다. 이번 작업 중
  UserGuide와 관련 있으면 정리하고, 아니면 손대지 않고 남긴다
