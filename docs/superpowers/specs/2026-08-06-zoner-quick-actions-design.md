# Zoner — 빠른 실행 블록 재설계 (HUD 타일)

**날짜**: 2026-08-06
**대상**: `src/components/Mypage.js`, `src/components/Mypage.css`
**선행**: 계측 장비 디자인 시스템 (커밋 `2c5d3d4..7b3c195`)

## 배경

Mypage의 "빠른 실행"은 이 서비스의 실질적 메인 진입점이다. AI 채팅·학습 시작·학습 기록·휴지통 네 개가 여기서 갈라진다.

그런데 현재 구현(`Mypage.css:472-507`)은 `min-height: 44px`, `--text-sm`, `--radius-full`인 작은 알약 버튼 4개가 `flex-wrap`으로 늘어선 형태다. 페이지에서 가장 중요한 블록이 가장 부차적으로 보인다.

두 번째 문제는 질감이다. 계측 장비 방향은 절제돼 있지만 "미래지향적·AI·혁신적" 인상에는 못 미친다. 특히 이 블록은 제품의 첫인상을 만드는 자리다.

## 목표

1. 빠른 실행을 페이지의 시각적 주인공으로 승격한다
2. 계측 장비 언어를 버리지 않고 **전투기 HUD 쪽으로 밀어붙여** 미래지향적 인상을 만든다
3. 정적인 버튼이 아니라 **반응하는 계기판**으로 느껴지게 한다

## 범위

**포함**: Mypage의 빠른 실행 블록 (마크업 + 스타일 + 보조 수치 계산)

**제외**:
- 다른 화면(Home, Save, Trash, Trashread) — 손대지 않는다
- `src/styles/tokens.css` — 새 토큰을 만들지 않는다. 기존 토큰만 조합한다
- Supabase 쿼리 — **변경 금지.** 아래 "데이터" 참조
- Mypage의 다른 섹션(집중도 요약, 최근 기록, 추천 서비스) 레이아웃

## 설계 결정과 근거

### 네 타일은 동등한 크기를 갖는다

주액션 1 + 보조 3의 위계 구조를 먼저 검토했고 권장했으나, **사용자가 동등한 4타일을 선택했다.**

프로젝트 규약 `design-quality.md`가 "균일한 간격에 위계 없는 기본 카드 그리드"를 금지 패턴으로 두고 있으므로, 크기 대신 **보조 수치**로 위계를 만든다. 살아있는 데이터가 붙은 타일(학습 시작·학습 기록)이 자연히 눈을 먼저 끈다.

### 넓은 화면에서도 2×2를 유지한다 (가정)

4열로 펴면 타일이 다시 납작해져 키운 의미가 사라진다. `max-width`로 블록 폭을 묶고 2×2를 유지한다. 320px에서만 1열로 떨어진다.

> 사용자가 명시 확정하지 않은 항목이다. 권고안으로 확정했으며, 변경 시 그리드 정의 한 줄만 바꾸면 된다.

### 휴지통 타일은 정적 문구를 쓴다 (가정)

"3일 후 2건 삭제" 같은 경고는 유용하지만 휴지통 전용 쿼리가 필요하다. 이번 범위는 쿼리 무변경이므로 정적 문구로 둔다.

> 위와 동일하게 권고안 확정이다. 경고 표시가 필요해지면 별도 후속 작업으로 뺀다.

```
└──────────────────┘  └──────────────────┘
┌──────────────────┐  ┌──────────────────┐
│ ◉                │  │ ⌦                │
│                  │  │                  │
│ 학습 기록         │  │ 휴지통            │

```

- 그리드: `repeat(2, 1fr)`, `gap: var(--space-4)`, 블록 `max-width: 720px`
- 480px 이하에서 `1fr` 1열로 전환
- 타일 `min-height: 140px`, `padding: var(--space-6)`, `--radius-lg`
- 내부 3단 세로 배치: 아이콘(상단) → 라벨 → 보조 수치
- 아이콘과 라벨 사이는 `margin-top: auto`로 벌려, 라벨 묶음이 하단에 고정된다
- 라벨 `--text-lg` / 보조 수치 `--text-sm` — 크기 대비로 둘을 구분한다

## 시각 언어 — HUD

| 요소 | 구현 | 기본 | 호버 / 포커스 |
|---|---|---|---|
| 코너 브래킷 | `::before`·`::after`에 각각 `border-top`+`border-left`, `border-bottom`+`border-right`. 변 길이 14px, 굵기 1px | 모서리에 붙음 (`translate: 0`) | `translate`로 대각선 바깥 4px 이동 |
| 스캔 라인 | 높이 2px, `linear-gradient(90deg, transparent, var(--color-accent), transparent)`. 타일에 `overflow: hidden` | `opacity: 0`, 타일 상단 위로 대기 | `translateY`로 위 → 아래 1회 통과 |
| 배경 격자 | `repeating-linear-gradient` 가로·세로 24px 간격, 선 1px, 알파 0.03 | 정적 | 변화 없음 |
| 아이콘 | 기존 글리프 유지, `--text-2xl`로 확대 | `--color-accent` | `filter: drop-shadow(0 0 6px …)` 청록 글로우 |
| 테두리 | `--color-border` 1px | — | `--color-accent` |

스캔 라인은 호버가 시작될 때 **1회만** 통과한다. 무한 반복하지 않는다 — 상시 움직이는 요소 4개는 페이지를 산만하게 만들고, 사용자의 시선을 집중도 요약에서 뺏는다.

Home의 격자 텍스처와 같은 언어를 쓴다. 새 색·새 토큰을 만들지 않는다.

## 모션

- **`:hover`와 `:focus-visible`이 동일한 효과를 발동한다.** 현재 구현은 호버에만 걸려 있어 키보드 사용자가 피드백을 덜 받는다. 이번에 맞춘다.
- 애니메이션 속성은 `transform`·`opacity`·`filter`로 제한한다. 레이아웃을 유발하는 속성은 쓰지 않는다.
- 지속시간·이징은 기존 토큰(`--duration-*`, `--ease-out-expo`)을 쓴다.

### reduced-motion

```
prefers-reduced-motion: reduce
  → 스캔 라인 비활성 (opacity: 0 고정)
  → 브래킷은 이동 없이 색상만 변경
  → 아이콘 글로우는 유지 (움직임이 아니므로)
```

**정보는 유지하고 움직임만 제거한다.** 호버 상태임을 알리는 신호 자체가 사라지면 안 된다.

## 데이터 — 새 쿼리 없음

Mypage가 이미 로드하는 `recentSessions` 배열만 쓴다.

**중요 — 이 배열은 `.limit(3)`이 걸려 있다** (`Mypage.js:75`). `id, started_at, focus_score`를 `started_at` 내림차순으로 최대 3건만 가져온다. 따라서:

- `recentSessions[0]`은 **가장 최근 세션**이다 ✅
- `recentSessions.length`는 **총 세션 수가 아니다** ❌ — 3건 이상 가진 사용자는 전부 "3"이 된다

초안에서 "학습 기록 → 총 34세션"을 계획했으나 **기존 쿼리로는 그 값을 낼 수 없다.**

대안으로 `started_at`을 써서 "마지막 학습 8월 5일"을 넣는 안을 검토했으나 **채택하지 않았다.** 옆의 "학습 시작" 타일이 이미 같은 세션(`recentSessions[0]`)의 점수를 보여주고 있어, 두 타일이 둘 다 "가장 최근 것" 이야기를 하게 된다. 그리고 "학습 기록" 타일이 알려줘야 할 것은 문 뒤에 무엇이 몇 개 있는가다.

**따라서 count 쿼리 한 줄을 추가한다.** `head: true`라 행을 전송하지 않고, 기존 세션 쿼리와 `Promise.all`로 묶으면 왕복 횟수가 늘지 않는다.

```javascript
const [{ data: sessions }, { count: totalSessions }] = await Promise.all([
  supabase
    .from('active_study_sessions')
    .select('id, started_at, focus_score')
    .eq('user_id', user.id)
    .order('started_at', { ascending: false })
    .limit(3),
  supabase
    .from('active_study_sessions')
    .select('id', { count: 'exact', head: true })
    .eq('user_id', user.id),
]);
```

| 타일 | 보조 수치 | 출처 | 빈 상태 |
|---|---|---|---|
| 학습 시작 | `마지막 세션 82%` | `recentSessions[0].focus_score` | `첫 세션을 시작하세요` |
| 학습 기록 | `총 34세션` | count 쿼리 | 0이면 `아직 기록이 없습니다` |
| AI 채팅 | `학습 도우미와 대화` | 정적 | — |
| 휴지통 | `삭제한 기록 복구` | 정적 | — |

**count가 `null`일 때(쿼리 실패)를 반드시 처리한다.** 이 경우 `기록 전체 보기`라는 중립 문구로 떨어뜨린다. `총 null세션`이 보이면 안 된다.

점수 색상은 `ScoreRing.js`가 이미 export 하는 `focusLevel()`을 재사용한다. 새 매핑 함수를 만들지 않는다.

**빈 상태를 반드시 처리한다.** 신규 사용자에게 `마지막 세션 undefined%`가 보이면 안 된다. `focus_score`가 `null`인 세션도 방어한다.

## 접근성

- `<button type="button">` 유지 (현재도 button이다)
- 보조 수치가 스크린리더에서 분리돼 읽히지 않도록 `aria-label`을 합성한다
  - 예: `aria-label="학습 시작, 마지막 세션 82퍼센트"`
  - 시각 텍스트는 그대로 두고 `aria-label`로 덮는다
- 브래킷·스캔 라인·격자는 전부 `aria-hidden="true"` 장식
- 보조 수치 색은 `--color-text-muted`(다크 배경 기준 실측 6.85:1) 이상
- 타일 전체가 클릭 타겟이므로 최소 터치 크기(24×24, 권장 44×44)를 여유롭게 넘는다
- 아이콘 글리프는 장식이므로 `aria-hidden`

## 코드 배치

`src/components/ui/`에는 넣지 않는다. 규약상 `ui/`는 도메인을 몰라야 하는데 이 타일은 Mypage 전용이다.

`MypageTopbar` 선례대로 `Mypage.js` 모듈 스코프 컴포넌트로 둔다.

보조 수치 계산은 **순수 함수로 분리한다** — `react-router-dom`을 import 하지 않는 모듈이어야 Jest에서 테스트할 수 있다(TS-003). 계산 함수를 컴포넌트 바깥에 두고 직접 export 하거나, 복잡해지면 `src/lib/`로 뺀다.

## 테스트

| 대상 | 검증 |
|---|---|
| 보조 수치 계산 | 세션 0건 / 1건 / N건 각각의 문구 |
| 점수 → level 매핑 | `focusLevel()` 재사용이 맞는 색 등급을 내는지 |
| 빈 상태 | `sessions`가 빈 배열일 때 `undefined`가 새지 않는지 |

컴포넌트 렌더 테스트는 이 저장소의 Jest 리졸버 제약(TS-003)상 불가하다. 순수 함수 단위로 커버한다.
