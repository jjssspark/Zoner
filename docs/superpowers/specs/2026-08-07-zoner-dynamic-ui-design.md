# 동적 UI — 학습 중·리포트 화면에 실시간 피드백 입히기

날짜: 2026-08-07
브랜치: `feat/dynamic-ui` (`feat/session-video-recording` 위에서 분기)
선행 문서: `2026-08-05-zoner-design-system-design.md`

## 이 문서의 위치

새 설계가 아니다. 디자인 시스템 스펙이 미뤄둔 작업이다. 그 문서는 두 화면을
명시적으로 제외했다:

> Read(리포트)와 StartLearning(학습 중)은 이번 범위에서 제외한다. 두 화면은
> 각각 서브프로젝트 3(집중도 원인 breakdown 표시)과 4(실시간 피드백)에서
> 기능이 추가되므로, 지금 디자인만 새로 입히면 곧 다시 뜯게 된다. 새 디자인
> 시스템 위에서 기능과 함께 한 번에 만든다.

그 기능들이 들어왔다. 집중도 원인 breakdown, 실시간 알림, 영상 녹화까지
완료된 상태다. 이 문서는 예고된 서브프로젝트 4(실시간 피드백)의 시각화
부분을 다룬다.

따라서 시각 언어를 새로 정의하지 않는다. 선행 문서의 토큰과 원칙을 그대로
따르고, 적용되지 않은 두 화면에 확장한다.

## 현재 상태

모션이 Mypage에 몰려 있다.

| 화면 | 모션 선언 | 비고 |
|---|---|---|
| Mypage | 24 | 디자인 시스템이 적용된 유일한 주요 화면 |
| Home · FAQ · Pricing | 5~8 | 부분 적용 |
| StartLearning | 2 | 알림 배너 진입만 |
| SessionReport | 1 | — |
| `ui/ScoreRing` | 2 | 마운트 시 0→목표값 채우기 **이미 구현됨** |

`ScoreRing`의 채우기 애니메이션은 선행 문서 요구사항대로 이미 있다. 이
문서에서 다시 만들지 않는다.

## 핵심 발견 — 실시간 집중도가 존재하지 않는다

학습 화면이 가진 실시간 상태는 `isFocused`(불리언), `elapsedSeconds`,
`activeAlert`뿐이다. 점수는 종료 시점에 `aggregateSession(ticks)`로 한 번
계산되고, 그전까지 틱은 `ticksRef`(ref)에 쌓이기만 해 화면에 나타나지 않는다.

두 가지가 이 작업을 가볍게 만든다.

1. `onTick`이 이미 매 틱 `setIsFocused`를 호출한다 → 리렌더가 이미 돌고 있어
   실시간 점수를 붙여도 렌더 비용이 새로 늘지 않는다.
2. `tokens.css`의 `--color-reason-*`가 `focusTracker.js`의 `REASON` 값과 1:1로
   이미 정의돼 있다. 선행 문서가 "정의만 하고 실제 사용은 리포트"라고 적어둔
   토큰이다 → 새 색을 만들 필요가 없다.

## 접근 — 파생 상태 + CSS 커스텀 프로퍼티

계산은 `src/lib/`의 순수 함수, 애니메이션은 CSS. 화면은 커스텀 프로퍼티만
인라인으로 내려주고 나머지는 스타일시트가 처리한다. 새 의존성 0개.

"화면 파일은 Jest 불가, 순수 로직만 `src/lib/`에"(TS-003) 제약과 맞물린다 —
새로 만드는 계산 함수는 전부 단위 테스트 가능하다.

애니메이션 라이브러리는 도입하지 않는다. 선행 문서가 이미 기각했고
(gzip 약 50kb는 마이크로사이트 JS 예산 80kb를 혼자 넘긴다), 현재 의존성
13개인 상태를 유지한다.

## 품질 기준

상용 수준의 완성도를 목표로 한다. 구체적으로:

- **모션은 정보를 전달할 때만 쓴다.** 장식적 움직임을 추가하지 않는다
- **튀지 않는다.** 집중도 색 전환은 `--duration-slow`(600ms)로 천천히 물든다.
  틱마다 색이 깜빡이면 학습에 방해가 된다
- **컴포지터 친화 속성만.** `transform`·`opacity`·`border-color`·
  `stroke-dashoffset`. 레이아웃 속성은 건드리지 않는다
- **색만으로 정보를 전달하지 않는다.** 집중 수준과 판정 원인은 색과 함께
  반드시 수치나 라벨을 동반한다 (선행 문서 접근성 항목)
- **모든 상태를 설계한다.** `hover`·`focus-visible`·`active`를 기본값으로
  두지 않는다

## 단계

### 1단계 — 공통 기반 (`src/lib/focusTracker.js`)

```
computeRollingFocus(ticks, nowMs, windowMs) → 0~100 | null
```

누적 평균이 아니라 **이동 창(기본 2분)**. 누적이면 30분 지나서 고개를 들어도
숫자가 움직이지 않아 실시간이라는 느낌이 사라진다. 창을 채울 틱이 없으면
`null`을 반환해 화면이 "측정 중"을 표시할 수 있게 한다.

밴드 매핑은 `ScoreRing.js`의 기존 `focusLevel()`(high/mid/low/poor)을 재사용해
`--color-focus-*`로 연결한다.

테스트: 빈 배열, 창 밖 틱 배제, 경계값(80/50/30), 창보다 짧은 세션, 전부 집중,
전부 비집중.

### 2단계 — 학습 중 화면

- 실시간 집중도 %를 매 틱 갱신, 밴드 색을 따라감. 수치와 라벨을 함께 표시
- 카메라 프리뷰 테두리가 집중도 색으로 물듦 (`--duration-slow` 전환)
- 상태 점을 현재 `reason` 색으로 (`--color-reason-*`)

### 3단계 — 리포트 화면

`ScoreRing` 채우기는 이미 있다. 추가한 것:

- 중앙 수치가 링과 함께 0에서 올라간다. 링이 CSS `--ease-in-out`으로 채워지므로
  숫자도 같은 곡선(`easeInOutCubic` 근사)에 `--duration-slow`와 같은 600ms를 쓴다
- 시간대별 그래프 막대가 왼쪽부터 30ms 간격으로 자란다. 높이는 인라인으로
  정해진 채 `scaleY`만 애니메이션한다 — `height`를 움직이면 매 프레임 레이아웃을
  다시 계산한다
- seek 버튼 막대에 hover 상태를 준다. 누를 수 있다는 신호가 없었다

rAF로 도는 카운트업은 CSS의 `prefers-reduced-motion` 블록이 막지 못하므로
`matchMedia('(prefers-reduced-motion: reduce)')`를 코드에서 직접 확인해 즉시
최종값을 보여준다.

**IntersectionObserver는 넣지 않았다.** 리포트는 짧은 페이지이고 그래프가
상단 근처라 로드 시점에 이미 보인다. 관찰자를 붙여도 거의 항상 즉시 발화하므로
실익 없이 복잡도만 늘어난다. 막대는 마운트 시 애니메이션한다.

### 4단계 — 화면 전환 + 전역 포커스

`react-router-dom` 13개 라우트를 `location.pathname`으로 키를 준 래퍼로 감싸
진입 페이드를 준다.

**`transform`은 쓰지 않는다.** 조상에 `transform`이 걸리면 `position: fixed`
자손의 기준이 그 조상으로 바뀐다. Mypage의 고정 배경, SignUp, ConfirmDialog가
전부 `fixed`라 전환 중에 배경이 튄다. `opacity`만 쓰면 그 문제가 없다.

전역 `:focus-visible`이 아예 없어 FAQ·Pricing·UserGuide의 인터랙티브 요소가
어두운 배경에서 포커스 표시 없이 동작했다. `.claude/standards/accessibility.md`가
정한 규칙을 `index.css`에 한 번 넣어 전 화면을 함께 해결한다.

**하지 않은 것**: 화면별 카드 stagger 진입. 라우트 페이드가 전 화면에 일관된
진입감을 주므로 화면마다 별도 연출을 더하면 오히려 산만해진다. 필요하면
별도 작업으로 뺀다.

## 모션 감소 대응

`tokens.css`가 `prefers-reduced-motion: reduce`에서 전역으로 애니메이션과
전환을 0.01ms로 죽인다. 1~2단계는 전부 CSS라 이걸로 충분하다. 3단계의 JS
애니메이션만 별도 대응이 필요하다(위 참조).

## 브랜치

`main`이 아니라 `feat/session-video-recording` 위에서 분기했다. 2단계가
건드리는 `StartLearning.js`가 영상 브랜치에서 281줄 추가된 상태라, `main`에서
따면 두 브랜치를 합칠 때 같은 파일에서 충돌한다. 영상 쪽은 전체 리뷰를
통과하고 수동 검증만 남아 토대로 삼아도 안전하다.

## 함께 고친 결함

설계와 별개로, 작업 중 드러난 기존 결함 두 건을 고쳤다.

- `--color-success`가 **어디에도 정의되어 있지 않았다.** `StartLearning.css`의
  "집중 중" 상태 점이 이 변수를 참조해 채움색이 없었고, 결과적으로 비집중일
  때만 빨간 점이 보였다. 2단계에서 배색을 `--color-reason-*`로 교체하며 해결됐다
- 전역 `:focus-visible` 부재 (4단계 항목 참조)

`src/App.css`는 CRA 기본 보일러플레이트(`.App-logo` 회전 등)이며 어디에서도
임포트되지 않는 죽은 파일이다. 이번 작업 범위 밖이라 건드리지 않았다.

## 범위

1~4단계 전부 구현했다. 실제 학습 세션을 띄운 시각 확인은 사용자 점검으로
남긴다 — 2단계의 실시간 게이지는 카메라 앞에 사람이 있어야 렌더된다.
