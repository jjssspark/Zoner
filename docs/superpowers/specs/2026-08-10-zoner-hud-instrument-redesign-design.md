# Zoner 계측기 HUD 재설계

작성일 2026-08-10 · 브랜치 `feat/marketing-pages-redesign` 이후 신규 브랜치 예정

## 문제

화면별 완성도가 아니라 **방향의 문제**다. 현재 `tokens.css`가 만드는 것은
다크 네이비(hue 260) + 시안 강조 + 균일 라운드(`--radius-md` 0.75rem) 조합이고,
이는 AI 대시보드 템플릿에서 가장 흔한 형태다. 어느 제품인지 구분되지 않는다.

사용자 표현 그대로: "전체적으로 뻔하고 맘에 안 든다".

부수적으로, 강조색 `--cyan-400`이 집중도 밴드의 "보통" 색과 **같은 값**이다.
화면의 시안이 상태 표시인지 UI 장식인지 구분되지 않는다.

## 방향

**계측기(instrument) 골격 + 절제된 HUD 레이어.**

- 골격: 모노스페이스 수치, 얇은 룰 라인, 낮은 채도 배경, 신호색 하나
- HUD 레이어: 모서리 잘린 패널, 대각 브래킷, 계측 격자, 세그먼트 인디케이터
- 신호색: 얼음빛 블루

레퍼런스(sci-fi HUD 벡터 팩)에서 **구조만** 가져오고 글로우는 최소로 쓴다.
글로우를 전면에 쓰면 영화 소품 그래픽이 되고, 매일 여는 학습 도구로는 못 쓴다.
후보 3단계(절제/중간/과함) 중 **중간**을 선택했다.

### 채택하지 않은 방향

| 방향 | 이유 |
|---|---|
| 에디토리얼(세리프 지면) | 리포트는 살지만 학습 중 화면·설정 화면이 약해진다 |
| 네오브루탈 | 스크린샷은 강하나 장시간 응시에 피로하다 |
| 종이(라이트) | 다크 단일 테마 규칙을 뒤집어야 한다 |
| 유리 레이어(글래스모피즘) | 이미 흔하고, 겹친 판 위 텍스트 대비 관리가 어렵다 |
| 강조색 바이올렛 | 밴드와 충돌은 없으나 AI 제품 클리셰 |
| 강조색 라임 | 밴드 "높음"과 충돌 |
| 강조색 시안 유지 | 밴드 "보통"과 충돌. 구조만 바뀌고 인상은 그대로 |

## 토큰 설계

### 중립 — 슬레이트(hue 235)

색상환을 260 → 235로 옮기고 채도를 낮춘다. 배경이 조용해져야 신호색이 산다.

```
--slate-950: oklch(13% 0.012 235)
--slate-900: oklch(17% 0.012 235)
--slate-850: oklch(21% 0.012 235)
--slate-800: oklch(25% 0.012 235)
--slate-700: oklch(31% 0.012 235)
--slate-500: oklch(56% 0.014 235)
--slate-400: oklch(68% 0.014 235)
--slate-50:  oklch(97% 0.004 235)
```

### 강조 — 얼음빛 블루(hue 250)

```
--ice-300: oklch(84% 0.09 250)
--ice-400: oklch(76% 0.12 250)
--ice-500: oklch(72% 0.13 250)   ← --color-accent
--ice-700: oklch(52% 0.14 250)   ← 인쇄(흰 배경) 전용
```

기존 `--cyan-400`은 삭제하지 않고 **의미를 좁힌다** — 집중도 밴드 "보통" 전용.

### 의미 토큰 매핑

컴포넌트는 이 이름만 참조한다. 원시 토큰을 직접 쓰지 않는다.

| 의미 토큰 | 값 |
|---|---|
| `--color-bg` | `--slate-950` |
| `--color-surface` | `--slate-900` |
| `--color-surface-alt` | `--slate-850` |
| `--color-border` | `--slate-700` |
| `--color-border-strong` | `--slate-500` (대비 재계산 후 확정) |
| `--color-text` | `--slate-50` |
| `--color-text-muted` | `--slate-400` |
| `--color-accent` | `--ice-500` |
| `--color-accent-hover` | `--ice-400` |
| `--color-on-accent` | `--slate-950` |
| `--color-accent-print` | `--ice-700` |

`--slate-800`은 격자·눈금 등 비텍스트 보조선용으로만 쓴다.

### 밴드는 유지

`--color-focus-high`(라임 145) · `-mid`(시안 200) · `-low`(앰버 80) ·
`-poor`(레드 25) 네 값과 tick reason 색은 그대로 둔다. 강조색이 250으로 빠지면서
충돌이 해소되므로 밴드를 건드릴 이유가 없다.

### 형태 — 균일 라운드 폐기

"뻔함"의 가장 큰 원인이다. 요소 종류마다 다른 형태를 준다.

```
--notch:    14px    /* 패널 clip-path */
--notch-sm:  8px    /* 작은 패널·칩 */
```

| 요소 | 형태 |
|---|---|
| 패널·카드 | `clip-path` 노치 (좌하·우상 모서리를 자름) |
| 버튼·입력·칩 | `--radius-sm` |
| 링·아바타·상태 점 | `--radius-full` |

### 타이포

- 모든 수치는 `--font-mono`(JetBrains Mono, 이미 로드 중). 자릿수가 흔들리지 않아야 계측기로 읽힌다
- 영문 라벨: uppercase + `--tracking-wide`
- 한글 라벨: `letter-spacing`만. **uppercase를 적용하지 않는다** (한글에 대문자 개념이 없어 무효다)

## HUD 레이어 — 절제 규칙

토큰이 아니라 **규칙**으로 못박는다. 토큰만 주면 화면마다 다르게 남발된다.

1. **계측 격자** — `body`에 1회. 불투명도 0.024 이하. 화면별로 다시 깔지 않는다
2. **브래킷** — 화면당 주 패널 **1개**에만, 대각 2개(좌상·우하). 모든 카드에 두르지 않는다
3. **글로우** — 주 수치의 `text-shadow` 1회. **테두리 글로우 금지**
4. **라이브 인디케이터** — 실제로 측정 중일 때만 표시. 장식으로 쓰지 않는다
5. **스윕 라인** — 실시간 데이터 위에만. 정적 리포트에는 쓰지 않는다

## 컴포넌트

`src/components/ui/` 에 추가한다. 라우터 의존이 없으므로 Jest 테스트 대상이다.

| 컴포넌트 | 책임 | 의존 |
|---|---|---|
| `HudPanel` | 노치 + 선택적 브래킷 래퍼 | 없음 |
| `Gauge` | 눈금 있는 선형 게이지 (0~100) | 없음 |
| `SegmentMeter` | 세그먼트 인디케이터 (n/total) | 없음 |

기존 `ScoreRing` · `Sparkline` · `ReasonBadge` · `Skeleton` · `ConfirmDialog`는
새 토큰에 맞춰 재스타일한다. 구조 변경은 하지 않는다.

## 적용 순서

각 단계마다 빌드 + 기존 테스트 통과를 확인하고 다음으로 넘어간다.

1. `tokens.css` 재설계 — 소비처 전수 확인 후 교체
2. `StartLearning` — 제품 본체. 새 언어가 여기서 성립하지 않으면 되돌린다
3. `Read` / `SessionReport` / `FocusChart` — 인쇄 규칙 포함
4. `Mypage` (735줄, 최대 CSS 파일)
5. `marketing` / `auth` / `chat`

## 미리 잡아둘 함정

**`clip-path`가 focus outline을 자른다.** 노치를 건 요소에 `:focus-visible`
outline을 걸면 잘려서 보이지 않는다. 노치는 안쪽 요소에, outline은 바깥 래퍼에
건다. `HudPanel`이 이 구조를 강제한다.

**인쇄.** TS-018에서 인쇄 배경 문제를 이미 겪었다. 리포트 PDF에서 계측 격자 ·
노치 · 글로우 · 브래킷을 전부 걷어내는 `@media print` 규칙이 필요하다. 강조색은
`--ice-700`으로 내린다 — 화면용 72% 명도는 종이에서 거의 안 보인다.

**대비 재검증.** 배경 색상환이 235로 바뀌면 `--color-border-strong`의 3:1 근거가
무효가 된다. 현재 주석에 적힌 "navy-500(56%)에서 surface 위 3.97:1 / surface-alt
위 3.54:1"을 슬레이트 기준으로 다시 계산하고, 주석도 새 값으로 갱신한다.

## 검증

- 기존 테스트 268건 통과, 빌드 성공
- 본문 대비 4.5:1, 큰 텍스트 3:1, 컨트롤 경계 3:1 — 계산 근거를 `tokens.css` 주석에 남긴다
- `prefers-reduced-motion: reduce` 에서 펄스 · 스윕 정지
- 키보드만으로 전 플로우 이동, focus outline이 노치에 잘리지 않는지 육안 확인
- 320 / 768 / 1024 / 1440 에서 오버플로 없음
- 리포트 인쇄 미리보기에서 HUD 장식이 사라지는지 확인

## 범위 밖

- 라이트 테마 추가 (프로젝트 규칙상 금지)
- 집중도 밴드 색 체계 변경
- 신규 의존성 도입 — 노치는 `clip-path`, 격자는 `linear-gradient`로 해결한다
- 기능·데이터 모델 변경. 이번 작업은 표현 계층만 건드린다
